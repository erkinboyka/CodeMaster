## 1. Бизнес-процессы

### БП-1: Регистрация и авторизация

**Цель:** Создание аккаунта и вход в систему

**Последовательность:**
1. Гость открывает страницу регистрации
2. Вводит: имя, email, пароль
3. Опционально: указывает навыки, роль (seeker/recruiter)
4. Проходит reCAPTCHA
5. Система проверяет уникальность email
6. Пароль хешируется (bcrypt, 12 раундов)
7. Запись создаётся в БД
8. Пользователь перенаправляется на страницу входа
9. Вводит credentials
10. Проверки: существует? → не заблокирован? → пароль верный? → не исчерпаны попытки?
11. Создаётся сессия (DB-driven, 24 часа)
12. Пользователь попадает на Dashboard

**Сущности:** User, Session  
**Результат:** Авторизованный пользователь

---

### БП-2: Прохождение курса

**Цель:** Обучение пользователя по программе курса

**Последовательность:**
1. Пользователь выбирает курс из каталога
2. Открывает страницу курса → видит уроки и прогресс
3. Переходит к уроку
4. Тип урока определяет контент:
   - video: воспроизведение видео + материалы
   - article: чтение статьи
   - quiz: прохождение теста (вопросы + варианты ответов)
5. При завершении урока → AJAX-запрос complete-lesson
6. Обновляется UserLessonProgress
7. Пересчитывается прогресс курса: (completed / total) × 100
8. При 100% — курс помечается как завершённый

**Формула прогресса:**
```
progress = (count(completed_lessons) / count(all_lessons)) * 100
```

**Сущности:** Course, Lesson, QuizQuestion, QuizOption, UserCourseProgress, UserLessonProgress

---

### БП-3: Сдача экзамена курса

**Цель:** Проверка знаний и получение сертификата

**Последовательность:**
1. Пользователь нажимает "Сдать экзамен" (доступно при 100% прогрессе)
2. Система загружает CourseExam (JSON с вопросами)
3. Вопросы и варианты ответов перемешиваются (shuffle)
4. Запускается таймер (time_limit_minutes)
5. Пользователь отвечает на вопросы
6. При отправке: система проверяет ответы
7. Рассчитывается балл: (correct / total) × 100
8. Если балл >= pass_percent → выдаётся Certificate
9. Certificate получает уникальный 40-символьный хеш

**Формула балла:**
```
score = (correct_answers / total_questions) * 100
```

**Формула хеша:**
```
hash = Str::random(40) // или md5(uniqid())
```

**Сущности:** CourseExam, Certificate

---

### БП-4: Прохождение дорожной карты

**Цель:** Структурированное обучение по пути развития

**Последовательность:**
1. Пользователь выбирает дорожную карту
2. Видит интерактивную визуализацию (узлы с x/y координатами)
3. Узлы связаны зависимостями (deps JSON)
4. Пользователь проходит доступные узлы (с учётом зависимостей)
5. Каждый узел содержит: урок + тест
6. При завершении узла → обновляется RoadmapUserProgress
7. Прогресс: % завершённых узлов
8. При 100% → выдаётся RoadmapCertificate

**Логика доступности узлов:**
```
node.isAvailable = node.deps.every(dep => completedNodes.includes(dep))
```

**Сущности:** RoadmapNode, RoadmapLesson, RoadmapQuizQuestion, RoadmapUserProgress, RoadmapCertificate

### БП-5: Выполнение кода (Judge0)

**Цель:** Проверка кода пользователя через внешний движок

**Последовательность:**
1. Пользователь пишет код в редакторе
2. Выбирает язык программирования
3. Нажимает "Выполнить"
4. Код отправляется на Judge0 CE API
5. Judge0 компилирует и запускает код
6. Возвращает: stdout, stderr, время выполнения, память, статус
7. При наличии test cases — автоматическая проверка

**Поддерживаемые языки (language_id):**
| Язык | ID |
|------|----|
| JavaScript | 63 |
| Python | 71 |
| Java | 62 |
| C++ | 54 |
| C | 50 |
| PHP | 68 |
| Ruby | 73 |
| Go | 60 |
| Rust | 73 |
| TypeScript | 74 |
| SQL | 82 |
| HTML/CSS | 61 |

**Сущности:** LessonPracticeTask, PracticeSubmission, ContestSubmission

### БП-6: Отклик на вакансию

**Цель:** Подача заявки на работу

**Последовательность:**
1. Пользователь находит вакансию
2. Просматривает детали (требования, обязанности, навыки)
3. Нажимает "Откликнуться"
4. Проверка на дубликат (нельзя откликнуться дважды)
5. Создаётся UserApplication (status: applied)
6. Создаётся VacancyChat для общения
7. Пользователь может загружать документы (PDF, DOC, изображения)

**Сущности:** Vacancy, UserApplication, VacancyChat, VacancyDocument

---

### БП-7: AI-собеседование

**Цель:** Подготовка к реальному собеседованию

**Последовательность:**
1. Пользователь выбирает тип (technical/behavioral/coding/system_design)
2. Выбирает уровень сложности (easy/medium/hard)
3. Нажимает "Начать"
4. Создаётся Interview (status: in_progress)
5. AI генерирует 5 вопросов через Gemini API
6. Пользователь отвечает на каждый вопрос
7. AI оценивает каждый ответ (0-100) с фидбеком
8. После 5 вопросов → итоговый балл (среднее) + комплексный фидбек
9. Interview помечается как completed

**Формула итогового балла:**
```
final_score = sum(question_scores) / count(question_scores)
```

**Сущности:** Interview, ChatMessage

---

### БП-8: AI-репетитор

**Цель:** Получение помощи по программированию 24/7

**Последовательность:**
1. Пользователь открывает виджет AI Tutor
2. Вводит вопрос
3. Сообщение сохраняется в chat_messages (role: user)
4. Берётся история (последние 20 сообщений)
5. Формируется запрос к Gemini API с system instruction
6. Gemini отвечает
7. Ответ сохраняется (role: assistant)
8. История обрезается до 50 сообщений

**Системная инструкция:**
```
You are an AI tutor for CodeMaster, an IT education platform.
Help students learn programming, explain concepts clearly,
provide examples, and guide them through their learning journey.
Be encouraging, patient, and thorough in your explanations.
```

**Сущности:** ChatMessage

---

### БП-9: Управление контентом (Admin)

**Цель:** Управление платформой

**Последовательность:**
1. Админ заходит в админ-панель (/admin)
2. Видит статистику (пользователи, курсы, вакансии, новые сегодня, заблокированные)
3. Управление пользователями: CRUD, блокировка, смена роли
4. Управление курсами: CRUD курсов и уроков
5. Управление вакансиями: CRUD вакансий
6. Управление уведомлениями: просмотр, удаление

**Сущности:** User, Course, Lesson, Vacancy, Notification

---

### БП-10: Сообщество

**Цель:** Общение пользователей

**Последовательность:**
1. Пользователь заходит в раздел "Сообщество"
2. Видит список постов
3. Может создать пост (заголовок + контент)
4. Может просматривать посты
5. Может комментировать
6. Может ставить лайки (toggle)
7. Подсчитываются просмотры

**Сущности:** CommunityPost, CommunityComment, CommunityPostLike

## 2. Потоки данных

### 2.1 Поток авторизации

```
Пользователь → Форма (email, пароль) → POST /login
→ LoginController@login → Валидация → Auth::attempt()
→ Проверка is_blocked → Проверка brute-force → Создание сессии
→ Перенаправление на /dashboard → DashboardController@index
→ Загрузка данных (курсы, заявки, уведомления) → Blade шаблон → HTML → Браузер
```

### 2.2 Поток прохождения урока

```
Пользователь → Страница урока → Завершение → AJAX POST /courses/complete-lesson
→ CourseController@completeLesson → Проверка авторизации
→ Создание/обновление UserLessonProgress → Пересчёт UserCourseProgress
→ JSON ответ → JavaScript обновляет UI (прогресс-бар, статус)
```

### 2.3 Поток выполнения кода

```
Пользователь → Редактор кода → POST /practice/submit
→ PracticeController@submit → Валидация (код, язык)
→ Отправка на Judge0 CE API → Ожидание результата
→ Парсинг ответа (stdout, stderr, time, memory)
→ Сохранение PracticeSubmission → JSON ответ → Браузер → Отображение
```

### 2.4 Поток AI-репетитора

```
Пользователь → Виджет AI Tutor → POST /ai/chat
→ AiTutorController@chat → Сохранение сообщения (role: user)
→ Загрузка истории (20 последних) → Формирование запроса к Gemini
→ Gemini API → Получение ответа → Сохранение (role: assistant)
→ Обрезка до 50 сообщений → JSON ответ → Виджет → Отображение
```

### 2.5 Поток отклика на вакансию

```
Пользователь → Страница вакансии → POST /vacancies/{id}/apply
→ VacancyController@apply → Проверка дубликата
→ Создание UserApplication (status: applied) → Создание VacancyChat
→ JSON ответ → Перенаправление на чат
→ VacancyChatController@show → Загрузка сообщений → Blade → Браузер
```

## 5. Безопасность

### 5.1 Аутентификация

- Хеширование паролей: bcrypt (12 раундов)
- Сессии: DB-driven, TTL 24 часа
- CSRF-защита: Laravel tokens
- reCAPTCHA: v2/v3 для форм регистрации/входа

### 5.2 Авторизация

- Middleware: auth (проверка сессии), admin (проверка роли)
- Policies: проверка владельца ресурса
- Row-level security: пользователь видит/изменяет только свои данные

### 5.3 Защита от атак

| Атака | Защита |
|-------|--------|
| Brute-force | 5 попыток → 15 мин блокировки |
| SQL-инъекции | Eloquent ORM (parameterized queries) |
| XSS | Blade экранирование ({{ }}) |
| CSRF | Laravel CSRF tokens |
| Path traversal | Storage::put() с валидацией |

### 5.4 Загрузка файлов

- Документы вакансий: PDF, DOC, изображения
- Аватары: изображения
- Валидация MIME-типа и размера

- Поддержка: Redis, Memcached, файлы
